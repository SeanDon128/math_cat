# 11. Risks & Mitigation Strategies

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **Scope creep** — trying to implement all 12 grades or extra modes | High | High | Hard-lock V1 to Grades 1–4 (already decided). Follow MoSCoW backlog (doc 10) strictly; treat anything not in Must/Should as out of scope until MVP is done and stable. |
| **Art becomes a time sink** (first pixel art attempt, perfectionism) | High | Medium | Build with placeholder rectangles/plain-color sprites first (Day 1). Only invest in real art during Day 2's dedicated art passes. Cap each asset to a fixed time budget (e.g., 20 min per cat pose); if over budget, ship the rough version and move on. CC0 asset packs are an acceptable fallback for backgrounds/icons if time runs out. |
| **Controller input bugs** (Xbox controller not recognized, wrong button mapping, focus issues in menus) | Medium | High | Use Godot's Input Map actions everywhere (never hardcode `Input.is_key_pressed`/joy button checks in gameplay code). Test with the real physical Xbox controller by end of Day 1, not just Day 2. Keep keyboard as the tested-first fallback path. |
| **Math content bugs** (wrong distractors, duplicate answer choices, ambiguous/negative results) | Medium | Medium | Centralize distractor dedup logic once in a shared helper, reuse across all generators. Run each new generator through the throwaway test script (doc 5 testing tip) printing 20+ sample questions before wiring into UI — visually eyeball for nonsense output. |
| **Grade progression feels wrong** (too fast/slow, demotion too harsh/lenient) | Medium | Medium | All thresholds (`PROMOTE_THRESHOLD`, `DEMOTE_THRESHOLD`, `START_LIVES`, session length) are named constants in one place (doc 5) — tune in seconds, not a refactor. Playtest the loop yourself repeatedly during Day 2 bug bash and adjust constants, not logic. |
| **Timer and lives feel redundant or confusing together** (two separate end conditions) | Low | Medium | Keep both counters visibly distinct in the HUD (clock icon vs. hearts) and always show the triggering reason on the Game Over screen so players understand which one ended the run. |
| **Time pressure / burnout** (first hackathon, solo, 2 days) | Medium | High | Follow the hour-blocked schedule (doc 9) with built-in breaks. Treat the "End of Day 1" MVP checkpoint as non-negotiable — if behind, cut Grade 4 content or a generator rather than skip sleep/breaks. |
| **Save file corruption/crash** on load | Low | Medium | `SaveManager` always validates JSON parse result and falls back to defaults (empty high scores, default volumes) rather than crashing; wrap file reads in existence checks. |
| **Blurry pixel art at 1280×720** (default Godot texture filtering) | Medium | Low | Set texture import filter to Off/Nearest project-wide at the start of Day 1 (doc 2), before any art is imported, so nothing needs re-importing later. |
| **Scene-transition bugs losing game state** (e.g., popups implemented as full scene swaps wipe timer/score) | Low | Medium | Keep Level-Up/Demotion/Pause as child overlay nodes within `Game.tscn`, not `change_scene_to_file` calls (doc 3) — only Title↔Game↔GameOver are full scene swaps. |
| **Running out of time before export/submission** | Medium | High | Schedule export + submission packaging explicitly as its own schedule block (Day 2, last 1–2 hours) with buffer before the deadline, not "whenever coding is done." Do a test export at end of Day 1 as a smoke test that the export pipeline itself works. |
| **Distractor generation infinite loop** (can't find 3 unique wrong answers for edge-case small ranges, e.g., addition near 0) | Low | Medium | Cap regeneration attempts (e.g., max 10 tries) in the dedup loop, then fall back to a guaranteed-safe distractor formula (`correct + fixed_offset` sequence) rather than looping forever. |
